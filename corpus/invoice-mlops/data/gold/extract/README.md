# Extraction gold set

40 synthetic invoice PDFs (`docs/gold-001.pdf` … `gold-040.pdf`) and their expected fields (`labels.jsonl`).

- Generated by `python -m src.extract.synthetic_docs --n 40 --seed 13 --out data/gold/extract --prefix gold`. Byte-reproducible.
- 2–4 pages each: one invoice page plus cover letter / terms / remittance pages that also contain amounts, dates and reference numbers.
- Layouts: 20 Spanish (`FACTURA`, `1.234,56 €`, `14 de marzo de 2026`), 13 "tax invoice" (vendor only in the footer, `Amount due: USD …`), 7 English. Currencies: 29 EUR, 7 USD, 4 GBP. 3 invoices have no invoice number, so the expected value is `null`.
- Fields: `vendor_name`, `invoice_number`, `invoice_date` (ISO 8601), `total_amount` (incl. VAT), `currency` (ISO 4217). `layout`, `invoice_page` and `n_pages` are metadata for the page-filter test, not extraction targets.

**Where the labels come from:** the values are written into the PDF by the generator, so `labels.jsonl` is correct by construction for what the generator meant to print. A human check is still needed for what a reader would see (for example a vendor name that only appears in a small footer): see the review checklist in `docs/walkthrough.md`.

No real customer data: every name, number and IBAN is invented (Faker).
